# 構成と制作の進め方

キャラごとに1リポジトリとし、共通コードは基準版を記録して複製する。将来の共通化は必要になってから行い、今回は複数キャラ管理アプリを作らない。

```text
AGENTS.md / CLAUDE.md / README.md
instructions/                     今回の依頼と制作仕様
character_materials/<id>/         元画像・差分・注釈（原本を保持）
live2d_ai/                        共通切り抜き・リグ生成
projects/<id>/                   専用マスク・parts_spec・rig_spec
viewer/                          描画と入力
tools/                           新キャラ用書き出し・ZIP生成
kamikan-bridge/                   中継と設定画面（制作時に統合）
reference_sources/               読解用。完成版として直接実行しない
docs/verification/               比較画像・検証条件・既知問題
dist/                            配布版（旧版を保持）
```

## 共通ソースのセットアップ（Codex/制作担当向け）

Pythonの仮想環境で `pip install -r requirements.txt`。PlaywrightとChromiumを用意する。
`python -m live2d_ai init character_materials/<id>/base.png projects/<id>` は存在しない新しいフォルダにだけ使う。
このinitは1パーツと±30度の雛形を作るだけ。下記の仕様へ変更し、画像を見てパーツとリグを設計する作業が必要。
`python -m live2d_ai build projects/<id>` で生成し、`python -m live2d_ai export projects/<id> -o dist/<id>_webcam.html` は従来Webカメラ版の書き出し。
iPhone版はそのコマンドで完成しない。参照のHTML・入力モジュール・中継を新キャラへ統合する。

## 現基準のパラメータ

| パラメータ | 範囲・役割 |
|---|---|
| AngleX | -5〜5度、顔の左右 |
| AngleY | -10〜5度、下〜上 |
| AngleZ | -5〜5度、首かしげ |
| BodyX / BodyY | -1〜1、全身の平行移動。見本は横±135px、縦±70px |
| EyeLOpen / EyeROpen | 0閉〜1開 |
| MouthOpen | 0閉〜1開、連続値 |
| MouthForm | 整数0あ / 1い / 2え、同時表示しない |
| Smile / Surprise | 0〜1、表情切り替え。口形選択とは分ける |

この一覧は新リグの契約として設定する。独自のBreath等は実コードを確認して範囲を記録する。
上向きで黒目だけを上へずらす連動はOFF。複雑な髪は独立した揺れOFFで始め、頭と体のつなぎ目を連続にする。

## iPhone経路と参照ファイル

VTube Studio → UDP11125 → Node中継 → WebSocket → 入力変換 → パラメータ → WebGL描画。
中継はiPhoneのUDP21412へ毎秒 `{"messageType":"iOSTrackingDataRequest","time":5,"sentBy":"KamikanBridge","ports":[11125]}` を送る。
公式形式は `FaceFound`、`Rotation/Position:{x,y,z}`、`BlendShapes:[{k:"JawOpen",v:0.5},...]`、`Hotkey` 等。未知フィールドを許容する。
中継のHTTP/WSは127.0.0.1:8765。ブラウザから `http://localhost:8765/` を開く。file:///では起動しない。Origin制限を緩めない。

- `viewer/tracking-input-v5.js`: 正規化、口・表情、平滑化、C較正、入力切り替え。
- `viewer/iphone-motion-v4.js`: 相対回転、3方向記録、上下混入抑制。最新版v5もこのモジュールを利用。
- `viewer/iphone-motion-v5.html`: 入力・描画・版確認の接続。
- `kamikan-bridge/src/bridge.js`: 公式UDP受信とWS転送。
- `kamikan-bridge/portable-motion-v5/`: 起動・設定UI・版/フォルダ/内容の一致確認。
- `tools/export_iphone_motion_v5.py`: 見本専用export。新キャラ用に作り直す。
- `tools/package_iphone_motion_v5_mac.py`: 配布構成の参考。実行には元リポジトリの依存物が必要。

回転は公式例のUnity Quaternion.Euler(-Rotation.y,-Rotation.x,Rotation.z)を踏まえ相対クォータニオンへ変換し、実方向を記録した基底で分離する。生JSONのx/yだけをモデル角度へ直結しない。
初回は正面→下→右→右かしげ。以後Cは安定した正面・閉口の較正。未設定時は推測して顔を回転させない。
左右/かしげが主なとき弱い上下を抑える処理は、意図した弱い複合上下も抑える制約がある。
位置・角度・口開きは時間基準で平滑化する。MouthFormは整数で切り替える。FaceFound=false/通信途絶では緩やかに正面・真顔へ戻す。
iPhone入力はカメラ処理をロードしない。Webカメラ入力だけ従来処理を遅延ロードする。

## 新キャラへ分離する必須項目

モデルID、APP_ID、HTML名、UI名、版表示、設定JSON名、IP設定の保存先、localStorageの較正/方向キー、モデルハッシュ、exportの入力/出力パス。
参照にはowl_prince、Lunaris、52パーツ、irisパーツ名、±90→135変更前提のassertがある。全て新キャラの現物に合わせる。
exportは新キャラの生成rigを読み、画像の埋め込みと入力の統合を行う。ルナリスの完成HTMLを新キャラの生成元にしない。
モデルSHAはビルド後に生成し、中継とモデルの版を一致させる。旧中継をappIdだけで使い回さない。
8765/11125を共用する初期方式では同時起動をサポートせず、別キャラ起動中は画面で終了/切り替えを案内する。他キャラや無関係なプロセスを自動停止しない。

## 段階

1. 素材・画角・部位・不足資料を確認し、静止で元絵に一致させる。
2. 顔・耳・髪・服を分離し、背景残りと輪郭をパーツ単位で確認。
3. 小さい顔回転、独立した全身移動、表情、必要な飾りだけの揺れを順に追加。
4. 入力統合、方向/閉口較正、版確認、GUI起動を整える。
5. 比較画像とソフトウェア検査の後、実機のiPhone・Mac・OBSで確認して配布する。
