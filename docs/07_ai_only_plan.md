# 07. AI だけで完結させる計画（現在の計画）

前提（確定）:
- 外注は使わない。イラストの編集・描き足し・リギングを、人の手でやることはしない。
- Cubism と VTube Studio には、こだわらない。
- 作業はすべて、AI（Claude Code）への指示で進める。あなたの役割は、確認と、AI にはできない操作（設定の許可、実機での動作確認）だけにする。

この前提で、`docs/00`〜`06` の Cubism 前提の部分（外注、手作業の仕上げ、Cubism リギング）は、**この計画で置き換える**。Cubism 向けの検査スクリプトは、将来 Cubism に切り替えるときのために残す。

## 先に伝えておくこと（品質について）
大手事務所の Live2D と同等の品質は、この前提では出せません。大手のモデルは、イラストレーターが動きを想定してパーツを描き分け、リガーが数百のパラメータを手で調整して作られています。AI だけで、**配信で使える水準（自然なまばたき、口パク、首振り、視線、髪とケープの揺れ）まで**は目指せます。そのうえで、品質の上限は次の2点で決まります。

1. 隠れている部分（前髪の下の目、髪の後ろの肌など）を、どれだけ自然に補えるか
2. 自動リグ（AI が作る動きの設定）の表現力

この2点は、各段階で画像を見て確認し、足りない部分は繰り返し改善します。それでも上限は、手作業のモデルより低くなります。

## 全体の構成

```
上半身の絵（済）
  ↓ ① パーツ分け（AI が画像処理で作る）
パーツごとの透過 PNG（役割名付き）
  ↓ ② 自動リグ（iki）
.iki モデル（まばたき・視線・口パク・首振り・揺れ）
  ↓ ③ トラッキング（MediaPipe、Web カメラ）
Web ページで、顔の動きに合わせて動く
  ↓ ④ OBS のブラウザソース
配信画面
```

| 部分 | 採用 | 理由 |
|---|---|---|
| 動きの仕組み | **iki**（MIT、商用利用可） | AI エージェントが操作することを前提に作られたオープンな 2D パペットエンジン。Claude Code から使える。この環境でも動く（Node 22 と Chromium がある）。**自分で描画して画像で確認できる**ので、人の目を使わずに確認を回せる |
| 顔のトラッキング | **MediaPipe Face Landmarker**（Apache-2.0） | Web カメラだけで、表情の係数（まばたき、口の開き、眉など）が取れる。iPhone は不要 |
| 配信 | OBS のブラウザソース | ローカルで動かした Web ページを、透過のまま取り込める |

### iki の現状（正直に）
- 0.x の初期版で、作者も「まだ本番向けではない」としています。形式が変わる可能性があるので、**バージョンを固定して使います**。
- モデルは、PSD ではなく、**役割名を付けた PNG**（顔、目、虹彩、眉、口、鼻、前髪、後ろ髪、胴体など）から自動リグされます。胴体の腕のパーツや、全身版（縦長のキャンバス）にも対応しています。
- 顔のトラッキングや OBS 連携は含まれません。この2つは、私が Web ページとして書きます。
- 動作確認用に、モデルを実際に描画してポーズごとの画像を出し、パーツの折れ・つぶれを数値で検査する機能があります。これを品質の確認に使います。

## 品質を上げるために、あとから足せるもの（任意）
- **画像生成 AI の追加**: 隠れた部分（前髪の下の目、閉じた目、口の中）は、画像処理だけの補完では不自然になりやすい部分です。ここに画像生成 AI を使うと、品質が上がります。この環境には画像生成の道具がないので、使う場合は、私が指示（プロンプトと参照画像）を書き、あなたが普段使っている生成サービスに入れて、出てきた画像をリポジトリに置く形になります。イラストの技術は要りません。
- **GPU での生成系の補助**（See-through など）: この環境から重みをダウンロードできないため、いまは使えません。ネットワーク許可を広げれば、一部は可能になります。

## あなたにお願いすること（最小限）

**いますぐ必要なもの: なし。** P1 と P2 は、この環境だけで進められます。

**P3 以降で必要になるもの:**
1. **Web カメラ付きの PC と Chrome**（トラッキングの確認用）。ページを開いて動かし、結果（画面の録画やスクリーンショット）を返してもらう。
2. **OBS Studio**（P5 の確認用）。
3. **顔が映る短い動画（30 秒程度）**: トラッキングの精度確認用。ご自身の顔を撮るもので、他の人には見せず、リポジトリにも入れない。撮りたくない場合は、P3 の確認は、実機で動かしてもらう形のみにする。

**判断してほしいもの（1つ）:** この計画で進めてよいか。進める場合、次は P1（パーツ分け）に入ります。

## P1 第 1 版の結果（2026-10-15）

- 役割別レイヤー: 顔（目・眉・口・髪を取り除いて肌で補完）、白目、虹彩、まつ毛、眉、口（閉じ・開き）、前髪（髪飾り・耳飾り・長い髪の上部を含む）、後ろ髪、胴体（首の補完付き）
- 作り方は `tools/extract_parts.py`（LaMa で補完）→ `tools/scale_layers.py`（0.85 倍に縮小。iki の読み込み上限 12MB に収めるため）→ `tools/rig_and_render.sh`（iki の自動リグと描画）
- iki の標準の表情: 笑顔 (smile)、驚き (surprised)、怒り (angry)、困り (sad)、笑い (laugh)。真顔は初期状態
- 頭の向きは、横（AngleX）・縦（AngleY）・傾き（AngleZ）が ±30°。体は ±10°
- 検査で見つかったもの: 全部の角度を限界まで組み合わせたとき、前髪の 1 か所がつぶれる（`hair_front` の三角形 1 個）。通常の動きでは起きない
- 既知の弱点: 眉は元の線ではなく、滑らかな形で描き直している（髪の線が交差していて抽出できなかったため）。左目のまわりに、まぶたのハイライトが薄い縁として残る。口を開けた絵はコードで描いたもの

## 作り方の変更（2026-10-15）: 元の絵を土台にする方式

**それまでの方式（元の絵をパーツに切り分けて組み立て直す）は、通常状態の時点で元の絵と別物になりました。**
目の形・まぶたの線・肌の陰影・口が変わり、眉や顔の継ぎ目が目立つ「貼り付けた」見た目で、実用になりませんでした。

現在の方式（`tools/build_overlay_model.py`）:
- **土台は元の絵そのもの。** 通常状態は元の絵と同じ見た目になる。
- 目（開き具合 75/50/25/閉じ・笑い目・見開き）、口（笑顔・への字・小開き・あ・い・う・え・お・大開き）、眉（上げ・怒り・困り）、フクロウの目は、ChatGPT で作った差分画像の**その部分だけ**を土台の上に重ねる。
- 頭の向き・傾き・体の揺れ・呼吸・髪の揺れは、**土台の絵を丸ごと滑らかに変形**して作る（頭を球とみなして回す近似）。重ねるパーツにも同じ変形を掛けるので、顔の中で位置がずれない。
- 重ね順は「開いている → 閉じている」で、下の層は不透明のまま残る。切り替えの途中で土台の目が透けることがない。

できないこと・弱い点:
- 視線（黒目の動き）は、黒目の画素だけを目の中で動かして作る（端では、まつ毛がわずかににじむ）。
- 頭の向きは、絵を変形して作るので、大きく回せない。アプリでは横 ±15°、縦 ±12°、傾き ±10° までに制限し、この範囲は変形の折れを数値で検査している（`tools/check_warp.py`）。
- 生成画像は元の絵と画素までは一致しないので、髪の毛の多い目のまわりで、重ねた範囲の縁がわずかに見えることがある。
- 耳飾り（左右）とリボン（鎖・宝石つき）は、振り子として頭の動きに遅れて独立に揺れる（`app/src/swing.js`、モデルの ParamEarL/ParamEarR/ParamRibbon）。
- 髪の房ごとの揺れは無い（髪全体の揺れだけ）。

## 立体感への取り組み（2026-10-15）
- 第 1 歩: 前髪（黒い髪の塊）を、顔より手前として余分に動かす「視差」を入れた（`DEPTH_GAIN`）。変形の検査は最小 0.51 / 最大 1.49 で、折り返しなし。効果は小さい。
- 本格的な立体化は、前髪・顔・後ろ髪を層に分け、隠れた部分を補完する必要がある（次の段階）。
