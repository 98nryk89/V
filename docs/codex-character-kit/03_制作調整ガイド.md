# 制作の順序と、今の品質を支えている点

## 流用する部分と作り直す部分

共通のWebGL描画、顔追跡、HTML出力、比較の進め方を流用します。
髪や顔の切り抜き、隠れた部分の補完、顔の奥行き、回転支点、耳・服との重なりはキャラごとに作ります。
ルナリスの座標・銀髪の色判定・マスクをコピーしても別キャラには合いません。

## 進め方

1. 元絵を調べる：透明度、キャンバス、差分の位置、欠けた部分、必要な素材を確認する。
2. 静止で再合成する：切り抜いた全パーツを重ね、元絵と同じ見た目を確認する。動きを先に増やさない。
3. 小さい回転：顔幅・顎・首に合う頭部形状と支点を決め、左右5度・上5度・下10度程度から試す。
4. 固定箇所：耳の肌・輪は頭と同じ動き、眉は肌と同じ変形。耳だけの物理揺れは付けない。
5. 髪：まず独立した物理揺れなし。頭から体への追従率を連続的に弱め、長髪に中間の段差を作らない。
6. 口・目：範囲を限定した差分で瞬きと口形を追加。口形そのものは混ぜず、開き量を連続制御する。
7. 追跡：正面較正、移動と回転の分離、弱い表情の誤反応防止、手動優先を確認する。
8. 出力と配布：単一HTMLと説明をまとめ、開発ビューアと完成HTMLの両方を確認する。

## よくある不具合の原因

| 症状 | まず確認すること |
|---|---|
| 髪を動かすと服まで動く | 髪のマスクが肩や襟の画素まで取っていないか。髪だけ表示して確認 |
| 下を向くと髪の残りが見える | 固定された体の下地へ元の毛束が残っていないか。髪を隠して確認 |
| 首かしげで長髪が分断される | 顔追従を途中で急に0にしていないか。追従の重みと呼吸時の一致を確認 |
| 耳が崩れる | 肌、輪、頭の奥行き・支点・変形が一致しているか。輪より上へ物理がかかっていないか |
| 眉の周囲が四角くぼやける | 矩形の表情パッチや前髪が眉を巻き込んでいないか。眉は肌に固定 |
| 襟が黒く汚れる | 首との透明な隙間、髪や影の混入、補完する色の誤りを確認 |
| アクセサリー裏が銀色の板になる | 本来透明な背景まで髪色で補完していないか。本物の髪と透明背景を区別 |
| タッセルや毛先がぼやける | アルファ縁、重複した下地、別絵との差分のずれを確認 |
| 腕が透ける | 上層だけフェードして下層の衣装がない領域が生じていないか。外周と接続を確認 |
| 口が重なって崩れる | MouthFormの整数選択と等値ゲート、開いている一形状だけの表示を確認 |
| 表情が勝手に変わる | 自動判定の初期設定、保持時間、手動優先を確認 |

不具合はパーツを一つずつ隠して原因を絞り、原因を直します。顔全体のぼかしで隠さないでください。
輪郭の境界を適当な矩形で切らず、元絵の線・透明度・明暗と領域を見て判断します。
見えていない髪・肌の補完は近似です。元絵の表現を復元できた範囲と、補完した範囲を区別します。

## 負荷について

顔認識と描画、OBSの負荷を切り分けます。同じ画面サイズで「追跡なし」「Webカメラ」「OBS併用」を比較します。
軽量化が必要なら表示解像度、フレームレート、物理、メッシュ密度を一項目ずつ検討し、画像と負荷を前後比較します。
このキットに新しい軽量描画機能が既に実装されている、という意味ではありません。
iPhoneへ顔認識を移してもPCの描画負荷は残るため、入力の切替だけで解決するとは限りません。

## 既存ルナリスの改修

referenceの完成HTMLは見本として固定しています。新キャラ用の素材・マスクはこのHTMLには含まれません。
完成HTMLには見本の描画用画像とrigは埋め込まれていますが、制作前のレイヤーや加工履歴まで復元できるわけではありません。
既存ルナリスの切り抜きから改修したい場合は、配布者から完全な制作データを受け取ってください。
