# iPhone動作設定版 v3

v2/v2.1の軸割り当てとv2.2の軸交換は、利用者の実機で方向が混線した。旧試験は仮定したraw軸を正しい物理方向として送り、それを同じ仮定で確認していた。v2.2の調整も上下をx/yだけから選び、残る軸を左右、zをかしげと決めていたため、この仮定自体が合わない入力を扱えなかった。

利用者の検品基準は「左右だけを動かしたら顔の向き上下は動かない。上下だけを動かしたら顔の向き左右は動かない」。診断値を貼る依頼は取り下げ、方向別の入力とモデルの実パラメータの両方を検査する。

## 入力変換の作り直し

`viewer/iphone-motion.js`で、公式Unity受信例のEuler(-Rotation.y,-Rotation.x,Rotation.z)をZ→X→Y順のクォータニオンへ変換し、現在姿勢×正面姿勢の逆回転から正面に対する回転ベクトルを求める。Eulerの数値を個別に引き算する方式は使わない。正面・下向き・右向き・右へのかしげを実際の受信から記録し、3つの方向ベクトルを正規化し、その逆行列で右向き/下向き/かしげへ分離する。固定x/y交換やz=かしげというモデルへの直結は使わない。方向の分離後に微小除外・感度・回転の上限を適用する。BodyX/Yや左右の上限はAngleYを決める条件にしない。

`viewer/tracking-input-v3.js`は、左右→AngleX、下向き→負AngleY、右かしげ→AngleZへ渡す。完成Webカメラ版と同じモデル側の方向・上限を使う。表情、口、まばたき、接続の再試行、Cによる正面記録、顔を失ったときの復帰を維持。初回設定中は頭の角度・位置移動を固定し、未検証の方向で動かさない。

`viewer/iphone-v3.html`は4姿勢を順に案内し、各姿勢を記録ボタンまたはスペースキーで記録する。0.3秒程度の安定した窓の中央値を使い、小さすぎる動き・似た方向の記録・不安定/古い/顔なし受信では先へ進まない。描画の負荷で受信処理が10fpsまで下がっても記録できるよう、直近の安定した末尾を最大0.6秒まで使う。上下軸の推測を増やす代わりに、初回だけ実動作との対応を画面内で記録する。

保存するのは方向ベクトルだけで、画像や顔の動画ではない。古いv2.2のlocalStorageは読み込まない。保存不可のブラウザでは現在のページで動作し、保存不可と表示する。次回は保存した方向を読み込み、Cは正面だけを更新する。iPhoneの持ち方を変えた場合などは画面から合わせ直せる。

画面上部に左右・上下・傾きの3値を追加し、下部の全パラメータと同じ実値を確認できる。

## 配布

旧版は変更しない。`dist/lunaris_iphone_motion_v3_update.zip`は、新しいモデルHTML（配布先の名前は従来のowl_prince_iphone_test.html）、新設定JSON、日本語手順、ハッシュ一覧だけ。中継・起動ファイル・Node・素材は交換しない。フォルダを複製して旧版保管後、使用中のhtmlへ2ファイルを入れ、接続画面から開いてv3表示を確認する。

再生成は `python tools/export_iphone_motion_v3.py` → `python tools/package_iphone_motion_v3_update.py`。

## 検証

新規Node試験では全48通りの軸順/符号、混合座標・非直交な方向、角度の循環、再基準化、保存/復元、不正な記録、低fpsを確認する。左右入力でAngleY/AngleZが0、上下入力でAngleX/AngleZが0であることを直接assertする。正面が3方向に傾いた基準から純粋な3D回転を作り、大きな左右入力と最大位置移動を与えてもうつむきへ流れないことを確認する。

ブラウザ試験は、旧Mac配布ZIPへ2ファイルだけ適用し、混合座標の模擬UDPを実中継→WebSocket→HTMLへ送る。画面の4姿勢記録を実行してから、右/左/下/上/かしげ/左右最大/かしげ最大/正面の8ケースで実モデルのパラメータを確認。補間が収束した値と入力目標値を両方記録し、上下または左右が0のままであることを確認する。記録は `/workspace/iphone-motion-v3-check/parameter-trace.json`、画像は同じフォルダ。

模擬入力だけで実iPhoneの身体動作まで確認したと主張しない。初回の4姿勢記録を必要とする版であり、追加操作ゼロで直った版とは説明しない。素材・モデル本体の描画は5姿勢で完成Webカメラ版と比較する。

最終確認は新規Node10件と旧関連62件、ブラウザ4件が成功。3方向に傾けた初期基準と混合座標を使った実経路のブラウザ確認で、収束後の左右入力はAngleY=0、上下入力はAngleX=0、かしげ入力はAngleX=AngleY=0だった。目標値と実値は `iphone-motion-v3-parameter-trace.json` を参照。5姿勢の完成版との描画ハッシュ一致と、右/下/上の画像を目視確認した。
