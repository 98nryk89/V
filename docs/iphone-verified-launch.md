# MOTION-3：実行する版を確認する起動セット

利用者はv2.2/v3へ更新しても動きが変わらないと報告した。実機の角度混線の原因を特定したとは断定しない。その調査中に、旧portable/run.jsがappIdだけで既存サーバーを再利用し、配信フォルダやモデルの内容を確認しない不具合をコード上で確認した。新しいフォルダの起動ファイルを開いても古いフォルダのHTMLを配信し続ける経路が存在した。

## 対応

- 原本を残してkamikan-bridge/portable-motion/へ起動処理を分離。
- モデルのSHA256、起動フォルダの実パス、中継の版でinstanceKeyを計算。同一内容・同一フォルダだけを再利用する。
- 別版/別フォルダのこの製品の中継は、既存の同一Origin POST /api/stopで終了してから新セットを起動する。無関係なサーバーは終了しない。切り替え失敗時は新しい版が起動したと報告しない。
- ZIP内のmodel-identity.jsonとHTMLのSHA256が一致しない場合は起動を拒否。htmlだけ、bridgeだけ、混在したセットの誤使用を検出する。
- 接続画面から開くモデルを固有名owl_prince_iphone_motion_v3.htmlへ固定。従来名は新ページへの入口だけにする。
- 接続画面とモデルにMOTION-3、フォルダ名、内容の識別値を表示。新HTMLは中継の版を確認できなければWebSocket追跡を開始しない。
- 方向設定の保存先を新しい名前へ分離し、過去v2.2/v3の誤設定を引き継がない。
- 頭の入力は既に作成したv3の相対クォータニオン＋3方向の記録を使用。初回は正面・下・右・右かしげを画面で記録する。未設定時の頭の角度/移動は0。上下/左右の新しい推測を追加しない。

## 配布

dist/lunaris_iphone_motion_verified_mac.zip。既存フォルダを複製してバックアップし、ZIPのhtml・bridgeの2フォルダを使用中のフォルダへ置き換える。既に許可して使っていた起動.commandは残す（ZIP同梱版も旧版とバイト一致）。起動.commandを開き直し、新しく開いたMOTION-3の接続画面からモデルを開く。以前のモデルのタブは閉じる。Node/npmの操作は不要。初めて起動.commandを使う場合のMacの署名/許可は別途必要。

再生成はpython tools/export_iphone_motion_verified.py → python tools/package_iphone_motion_verified_mac.py。

## 検証

Nodeの起動試験5件と方向変換10件、実パッケージの起動試験1件、実中継/ブラウザ試験5件。実パッケージ試験は旧配布ZIPのNode起動→新ZIPのNode起動→別フォルダの同じ新ZIPという順で実行し、旧プロセスの終了、新しいinstanceKeyへの切り替え、配信HTMLと配布HTMLのバイト一致を確認する。改変されたHTMLの起動拒否も確認。

ブラウザ試験は新ZIPだけから起動し、以前の有効だが誤った方向設定があっても初回記録へ入ること、4姿勢の記録、左右入力時AngleY=0、上下入力時AngleX=0、かしげの分離、保存/再読み込み/C、表情、5姿勢の旧描画一致、旧中継への接続拒否を検査。画像は/workspace/iphone-verified-check/。

実iPhoneの身体動作はこの環境から操作・観測できない。以上は実行版の切り替えと検証用入力での確認であり、利用者の実機で解消したという報告ではない。
