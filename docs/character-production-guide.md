# 別キャラ制作・メンバー共有用 指示書

更新: 2026-10-18。対象: このリポジトリのWebGLビューアで動く「Live2D風モデル」。現モデルの基準は `e780a07a92feabe116af2c371d6b95dddacba268`（髪を揺らさない版）。

制作ツールの参照先: [98nryk89/V の基準版](https://github.com/98nryk89/V/tree/e780a07a92feabe116af2c371d6b95dddacba268)。制作担当には、このリポジトリを利用できる状態で渡してください。指示書だけでは制作ツールは含まれません。

この文書と [制作依頼シート](character-request-template.md) を制作担当・Codex・Claude Codeに渡してください。利用者には完成HTMLと操作説明、制作担当にはリポジトリと元画像・仕様・マスクも渡します。HTMLだけでは切り抜きの作り方や修正履歴を引き継げません。

## 1. 流用できるものと作り直すもの

| 流用する仕組み | キャラごとに作り直す内容 |
|---|---|
| WebGL描画・HTML出力 | 元絵、表示範囲、パーツの重なり順 |
| Webカメラ追跡・正面較正 | 顔・髪・耳・服の切り抜き、隠れた部分の補完 |
| 顔の回転と全身移動の分離 | 顔の形・奥行き、首の支点、各部の座標 |
| 滑らかな口開閉、口形の排他表示 | 各口形・まばたき・表情の参考画像と位置合わせ |
| 表情の保持時間・誤反応を抑える判定 | 個人のカメラ環境での感度確認 |
| Git履歴・比較画像による検品方法 | そのキャラ専用の検証座標・マスク・期待結果 |

**元絵を別画像に差し替えるだけでは完成しません。** サンプルの銀髪と肌を分ける色条件、耳の位置、髪を固定する高さなどは、そのキャラ専用です。拡大縮小だけで合うとも限りません。

本方式は独自形式の `rig.json` とPNG、または単一HTMLを出力します。Live2D Cubismの `.moc3` 出力・VTube Studioへの読み込み機能はありません。

## 2. 最初に用意するもの

### 制作を始めるための必須素材

| 素材 | 条件 |
|---|---|
| 正面の元絵1枚 | 真顔・開眼・閉じ口が基本。顔、頭頂、必要な髪・服が切れていないもの。実際の透明度を持つPNGを優先 |
| 制作依頼シート | 動かす範囲、髪を固定するか、口形、表情、納品先を記入 |
| 利用条件 | その絵を加工して配信・動画・メンバーへの共有に使える範囲を確認して伝える |

元絵1枚でも着手できます。ただし、隠れた耳・肌・髪や閉じ目などが不足するため、補完と確認の手間が増え、今回と同じ仕上がりが自動で得られるわけではありません。

解像度は元の高画質データを使い、スクリーンショット・JPEGへの変換・無理な拡大は避けてください。新しく用意するなら長辺2000px程度以上が目安ですが、必須値ではありません。最終表示サイズに対して目・口・毛先に十分な画素があることを優先します。

**透明背景に見える市松模様が、画像そのものに描き込まれている場合があります。** 画像編集ソフトで背景色を変えて確認してください。白背景・市松背景しかない場合も相談できますが、特に白髪・銀髪の細い毛先は背景除去で欠けやすくなります。

### 今のモデルに近づけるため、強く推奨する素材

| 素材 | 欲しい内容・目的 |
|---|---|
| 髪だけの透明PNG | 前髪・横髪・後ろ髪・長髪。耳飾り・服・髪飾りと区別できると切り抜きやすい |
| 髪を外した肌のPNG | 顔・耳・首。前髪や耳飾りの裏に隠れる範囲も描いてあると、動いた際の穴を防げる |
| 閉じ目 | 左右とも完全に閉じた状態。途中の25/50/75%程度もあると段階的な瞬きが作りやすい |
| 「あ」「い」「え」の口 | 現方式の3口形を使う場合。各1枚、歯・舌・口内も描いたもの。元の閉じ口は正面絵を使う |
| 笑顔・驚き顔 | 追加する表情だけ用意。驚きは見開いた目、笑顔は希望する笑い目の形を示す |
| 耳・アクセサリーの区別画像 | 元絵のコピーへ色を塗り、耳の肌・輪・揺らす鎖や宝石・髪を区別。注釈を元絵へ直接焼き込まない |

切り抜きレイヤーは元絵と同じ絵の画素を使うのが理想です。「髪を消した肌」は隠れていた部分の描き足しを含んで構いません。別々に画像生成して顔つき・髪型まで変わったものは、位置合わせだけでは一致しません。

**閉じ目や口形・表情の差分は、元絵と同じキャンバスサイズ・位置・縮尺で、変更箇所以外を変えないでください。** パーツを小さく切り詰めた画像しかない場合は、元絵上の貼り付け位置も付けてください。背景や髪の線まで変わると、切替時に四角い境界・二重線が出やすくなります。

### あれば役立つ追加素材

- レイヤー付きPSDなどの原本。現ツールがPSDを直接読み込むわけではないので、使う層は同サイズの透明PNGにも書き出す。
- 同じデザインの横顔・斜め顔・下向きの参考絵。奥行きや正しい耳の位置を判断する資料であり、自動で横向きを生成する機能ではない。
- 耳飾り・髪飾り・リボンの単独レイヤーと、重なり順の説明。
- 肩の動物などを動かす場合、その閉じ目。動物がいないキャラにフクロウ用のパーツや操作は追加しない。

### 素材の渡し方の例

```text
character_materials/
  brief.md                # 記入済み制作依頼シート
  source.png              # 正面・開眼・閉じ口、透明PNG
  hair.png                # 髪だけ。可能なら前髪/後ろ髪/長髪を分ける
  skin.png                # 髪を外した顔・耳・首
  blink_closed.png
  blink_25.png            # 任意。25は「閉じ具合」など意味も明記する
  blink_50.png
  blink_75.png
  mouth_a.png
  mouth_i.png
  mouth_e.png
  smile.png
  surprised.png
  annotations.png         # 耳・耳飾り等を色分けした元絵のコピー
  references/             # 任意。横顔・うなずきなど
```

不足しているものは「なし」と書いてください。表情差分は全身画像でも目・口だけの透明レイヤーでも構いませんが、位置が分かることが必要です。

## 3. 今のモデルを基準にする場合の仕様

以下は初期案です。新キャラへの固定要件にするかは依頼シートで決めます。

| 部位 | 現モデルの動作 |
|---|---|
| 顔 | 左右・首かしげ±5度、上5度・下10度。平行移動とは分離 |
| 全身 | 横±90px・縦±70px。これは現画像サイズの値なので、新キャラでは表示サイズに合わせる |
| 髪 | 髪だけの物理揺れなし。頭髪は顔に追従し、耳下から徐々に抑えて胸元以降は服と一緒に動く |
| 眉 | 肌に固定。眉単独の表情・カメラ追従は行わない |
| 耳 | 肌と取付金具を頭に固定。耳単独では揺らさない |
| 耳飾り | 輪より下の鎖・宝石だけ、必要に応じて小さく揺らす |
| 口 | 閉じ口と「あ」「い」「え」。開いている形は同時に混ぜず1種類だけ。開き具合は滑らか |
| 瞬き・黒目 | 鮮明な瞬き。黒目は頭・全身移動に応じてごく小さく追加移動し、目の外にはみ出させない |
| 自動表情 | 笑顔と驚き。強めの表情を短時間保持して起動。両方同時なら驚きを優先 |
| 手動表情 | 1=笑顔、2=驚き、0=真顔。手動操作で自動表情を止め、リセットで再び有効 |

カメラの口形判定は顎・唇の形からの推定です。音声から母音を識別する機能ではありません。話者・照明・カメラで判定の出やすさが変わるので実機で調整します。

```text

最初にAGENTS.md・CLAUDE.md・docs/character-production-guide.mdを読み、
履歴上の古い仕様と最新仕様を区別してください。今回の依頼シートを優先します。

共通ビューアやカメラ追跡を変更する場合は既存キャラへの影響も確認してください。

足りない素材を一覧化し、作業可能な部分を先に進めてください。
隠れた肌や髪の補完が必要な場合は、補完した範囲を記録してください。

髪はまず揺らさず、頭の髪だけ顔について動き、長髪は滑らかに体へつなげてください。

静止・上下左右・下向き＋かしげ・まばたき・口・表情・呼吸を描画し、

並行作業はブランチと担当ファイルを分け、同じ生成物を同時に書き換えないでください。

最終納品はカメラ付き単一HTML、操作説明、比較画像、素材一覧、
パーツ・リグ・頭部形状の仕様、再生成手順、未確認事項、戻せるコミット番号です。
Chromeの実カメラとOBSでの短い録画は、できたことと未検証を分けて報告してください。
```

## 5. 制作の順序と検品

1. 元絵・差分画像を開いて確認し、透明度、位置、画素サイズ、足りない部分を調べる。原本を保存し、加工は別ファイルにする。
2. 髪・顔・耳・服・飾りへ分ける。まず全て静止のまま再合成し、元絵と比較する。髪だけ／髪なしの表示で、服側へ毛束が残っていないか確認する。
3. 新キャラの顔幅・顎・首の位置から頭部形状と回転支点を決める。小さい回転から試し、耳・眉・輪郭・白い襟のずれを確認する。
4. 頭髪は顔へ追従させ、長髪は連続的に体へつなぐ。耳の高さで急に追従を切って段差を作らない。呼吸でも服と長髪が離れないか確認する。
5. 瞬き、閉じ口と指定口形、表情を一つずつ追加する。目・口だけを差し替え、眉や前髪を巻き込まない。黒目を動かすときは元の黒目を下地に残さない。
6. 自動判定を接続し、正面較正、閉じ口への復帰、弱い表情での誤反応、手動優先、顔を画面外にした際の動作を確認する。
7. HTMLを出力し、制作中のビューアと出力HTMLの両方を確認する。最大移動で頭頂や毛先が切れない表示余白を設ける。
8. 利用者のPCでWebカメラ・OBSの短い録画を試し、完成版と直前の比較版を保存する。

最低限の比較画像は「元絵／静止」「下向き」「左右向き」「左右かしげ」「下向き＋かしげ」「口の0/25/50/75/100%」「完全閉眼」「笑顔／驚き」です。髪や耳飾りを揺らす仕様なら、止め絵だけでなく連続動作も確認します。

過去の失敗として、暗い色を全て髪・飾り扱いすると眉や服まで動きます。補完へ髪色が混ざると耳や襟が汚れ、広い矩形の表情パッチは眉周辺を四角くぼかします。症状が出たらパーツを一つずつ隠して、描いているパーツを特定してから直します。

## 6. 制作者向けのファイルとコマンド

| ファイル | 役割 |
|---|---|
| `projects/<id>/parts_spec.json` | 元画像パス、切り抜き、重なり、参考パーツ、隠れた部分の補完 |
| `projects/<id>/rig_spec.json` | パラメータ、回転・移動・透明度・物理の適用 |
| `projects/<id>/head_model.json` | キャラ専用の頭部形状。方式に応じて用意する |
| 同フォルダ内のPNG・領域JSON | そのキャラ用のマスクと補完画像。生成元と生成順も記録 |
| `viewer/runtime.js` / `viewer/tracking.js` | 全キャラ共通の描画／追跡。変更は既存キャラへ影響する |

以下はリポジトリ直下で実行します。制作者のPC向けの例で、Python環境とChromiumが必要です。利用者は通常Pythonを入れる必要はありません。

```sh
python -m pip install -r requirements.txt
python -m live2d_ai init character_materials/source.png projects/new_character
```

**initの引数は「画像→プロジェクト」の順です。** 初期状態は全身1パーツの雛形で、顔追跡付きの完成リグではありません。initは既存仕様を書き換えるので、存在しない新しいプロジェクト名にだけ実行してください。雛形の回転上限は±30度のため、まず±5度程度へ抑え、カメラ側の上限との整合も確認します。

パーツと動きの仕様を新キャラ用に作成した後:

```sh
python -m live2d_ai build projects/new_character
mkdir -p dist
python -m live2d_ai export projects/new_character -o dist/new_character.html
python -m live2d_ai preview projects/new_character --poses "left:AngleX=-5;right:AngleX=5;down:AngleY=-10;tilt:AngleZ=5;blink:EyeLOpen=0,EyeROpen=0" --out /tmp/new_character_check
```

プレビューは必要に応じて `CHROME_PATH` へ既存Chromiumの実行ファイルを指定します。開発用サーバーが必要な場合は制作者のPCで `python -m live2d_ai serve projects/new_character` を実行します。クラウド環境のローカルURLを利用者への共有先にはしません。

このクラウドのPythonは `/workspace/.venvs/live2d/bin/python`、Chromiumは `/usr/bin/chromium` です。新しいPCではそのPC用の仮想環境を用意し、これらの絶対パスはコピーしません。

`tools/refine_*.py` の既存スクリプトにはowl_prince専用のパス・座標・銀髪の色条件があります。新キャラの素材へそのまま実行せず、必要な処理を新キャラ用に分離します。サンプルのマスクPNGも新キャラへ貼り付けません。

既存モデルを守る回帰確認はビルド・HTML出力後に次を実行します。

```sh
python -m unittest discover -s tests -v
node --test tests/tracking.test.cjs
```

現時点の基準はPython25件とNode19件。既存テストの多くはowl_prince専用の座標を検査するので、新キャラが正しい証明にはなりません。新キャラでは、そのキャラの画像・動作の確認を別途行い、元絵との一致度を測る際も顔・目の領域を合わせます。サンプルのPSNR値を全キャラ共通の合格基準にしません。

## 7. 利用者向け: ChromeとOBSでの使い方

1. カメラ付きの完成HTMLを保存してChromeで開く。`*_artifact.html` はカメラUIを除いた埋め込み用なので選ばない。
2. 「Webカメラ追跡」の「開始」を押してカメラを許可し、追跡中になることを確認する。真顔・閉じ口で正面を向き、「正面を較正」を押す。
3. 「背景切替」で現ビューアの緑背景にする。緑色がキャラにも含まれるなら、別背景色の追加を制作担当へ依頼する。
4. OBSに「ウィンドウキャプチャ」を追加してChromeの表示を選ぶ。OSによっては同等の画面取得ソースを使う。モデル領域だけにクロップし、操作パネル・カメラ映像を映さない。
5. クロマキーフィルターで背景の緑を指定して抜き、ゲーム画面などの上に配置する。細い髪や宝石が消えない程度に調整する。
6. 30秒程度録画し、瞬き・会話・顔移動・背景の抜け・負荷を確認する。Chromeは最小化せず動作を確認する。キー1/2/0はChromeにフォーカスがあるときの操作で、OBSのグローバルホットキーではない。

モデルの画像・描画コードはHTMLに含まれますが、カメラの顔認識は外部のMediaPipe関連ファイルを読み込みます。現実装は `cdn.jsdelivr.net` と `storage.googleapis.com` への通信が必要で、完全オフライン用ではありません。カメラ許可が使えない環境では、制作担当が利用者PC上の開発用サーバー等で動作確認します。

OBSのブラウザソースへ直接入れる方法は、カメラ許可・透過・操作方法を別途検証してから採用してください。今回の基準はChromeの表示を取り込む方法です。**現在の確認済み範囲はChromiumの描画と模擬追跡入力で、実Webカメラ＋OBSでの録画は利用者PCでの最終確認が必要です。**

## 8. 納品と戻し方

納品物は、完成HTML、操作説明、素材一覧、元画像と参考画像、パーツ・リグ・頭部形状の仕様、マスク生成元・再生成順、比較画像、動作確認結果、未完了事項、確定コミット番号です。配信する人には完成HTMLと操作説明、修正する人には残りの制作データも渡します。

制作中は専用ブランチを使い、1コミット1目的とします。良かった版のHTMLは別名で保管し、「試験版の変更コミット」だけを `git revert <コミットSHA>` で戻せる状態にします。Gitなしでも前版HTMLを開き直して比較できます。

共有時は依頼シートに担当を明記します。並行作業では同じブランチへ同時にpushせず、パーツ切り抜き・動き・共通追跡などの担当箇所を分けます。同じJSONや生成HTMLの同時編集を避け、統合後にビルドとHTML出力を行います。
