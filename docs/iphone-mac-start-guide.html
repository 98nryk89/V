フクロウの王子
Mac＋iPhoneのVTube Studio 起動セット

2026年10月22日 / 接続画面 1.0.0。前回のiPhone試験モデルをそのまま使い、起動とIP設定を簡単にした版です。

ZIPを解凍 →「起動.command」をダブルクリック → ブラウザでiPhoneのIPを保存 →「モデル画面を開く」→ 正面でCキー。
npmやJSONの手作業は不要です。ターミナルは自動で開きますが、コマンドを入力する必要はありません。

1．初回の準備

  • Google Chrome、iPhoneのVTube Studio、同じWi-Fiへ接続したMacとiPhoneが必要です。
  • Node.js 22以上がMacへインストール済みである必要があります。以前の中継でnpm startを使えたMacは通常そのまま使えます。Node.js自体はこのZIPへ内蔵していません。
  • Node.jsがない場合、「起動.command」がNode.jsの公式ページを開きます。LTS版のMac用インストーラ（.pkg）を画面の案内に沿って入れ、起動ファイルを開き直します。ターミナルへインストール用のコマンドを貼る必要はありません。
  • 以前のkamikan-bridgeが起動中なら、そちらのターミナルでControl＋Cを一度押して終了します。古い中継を動かしたままだと同じポートを使えません。

2．起動する

  1. 受け取ったZIPをダブルクリックして解凍し、Lunaris_iPhone フォルダ全体をデスクトップなどへ保存します。中のファイルだけをばらばらに移動しません。
  2. 「起動.command」をダブルクリックします。Chromeで「フクロウの王子｜iPhone接続」が自動で開きます。
  3. Macが初回の実行許可を求めた場合は、画面に出る正規の許可手順で、この配布ファイルを確認して許可してください。「システム設定 → プライバシーとセキュリティ」に個別の「このまま開く」などが出る場合もあります。セキュリティ機能を全体で無効にする必要はありません。
  4. 黒い文字のターミナル画面が出るのは正常です。入力せず、利用中は閉じずに置いてください。

自動で開かなかった場合は、Chromeのアドレス欄で http://localhost:8765/ を開きます。同じセットを再びダブルクリックしたときは、起動済みの接続画面を開きます。

3．iPhoneと接続する

  1. iPhoneでVTube Studioを開き、顔を映してトラッキングを開始します。
  2. VTube Studioの設定で「3rd Party PC Clients」を有効にし、要求先UDPポートを21412にします。iPhoneのローカルネットワーク許可が出たら許可します。
  3. iPhoneの「設定 → Wi-Fi → 接続中のネットワークの ⓘ → IPアドレス」でIPv4を確認します。例は192.168.1.100です。MacのIPやアプリのポート番号とは別です。
  4. Macの接続画面へそのIPを入力し、「保存して接続」を押します。設定ファイルを開く必要はありません。
  5. 「接続済み・顔を検出しています」と受信fpsが表示されるか確認します。次回は保存済みのIPへ自動で要求します。Wi-FiなどでIPが変わったときだけ入力し直します。

iPhoneはVTube Studioを前面表示したまま使ってください。Macのファイアウォール等が接続許可を求めたら、Node.js/中継の通信を利用環境に応じて許可します。UDP受信は11125番、ブラウザのHTTP/WebSocketはMac内の8765番です。

4．モデルの動きを確認する

  1. 接続画面の「モデル画面を開く」を押します。キャラクターが別タブで開きます。以前と同じiPhone試験モデルです。
  2. 正面・真顔・閉じ口になり、モデル画面をクリックしてCキーか「正面・真顔を記録」を押します。
  3. 左右を見る、上・下を向く、首をかしげる、横・縦へ移動する、左右の瞬き、口「あ・い・え」を確認してください。眉は肌に固定、髪の独立した揺れは止めてあります。
  4. 笑顔は自動です。驚きはiPhoneのホットキー2でON。iPhoneの3で真顔、4で自動笑顔へ戻します。Macのモデル画面にフォーカスがある状態では、1=笑顔、2=驚きの切り替え、0=真顔も使えます。
  5. 動きが逆ならモデル画面の「左右/上下/傾き反転」、動きが大きければ各感度を調整します。「滑らかさ」を増やすと揺れが減り、追従は遅くなります。口形は近似判定で音声の母音識別ではありません。

顔を見失ったり通信が切れたりするとゆっくり真顔・正面へ戻ります。通信要求とWebSocketの再接続は続けます。ブラウザのページを更新したら、Cキーで基準を合わせ直してください。

5．OBSへ取り込む

  1. モデルのタブを別のChromeウィンドウへ移すと、設定画面と分けて取り込みやすくなります。
  2. OBSの「ソース → ＋ → macOSスクリーンキャプチャ」で、モデルを表示したChromeのウィンドウを選びます。
  3. 一覧が空の場合、Macの「プライバシーとセキュリティ → 画面収録」または「画面とシステムオーディオの収録」でOBSを許可し、OBSを再起動します。
  4. 「クロップ／パッド」で操作パネルやChromeの枠を除き、モデルに動く余白を残します。
  5. モデルの背景切替で緑にし、OBSの「クロマキー」のカスタム色に#00ff00を指定します。このiPhone試験版の緑は、旧Webカメラ完成版の#6fcf97とは異なります。
  6. 短く録画し、髪・宝石の抜け、口・瞬き・動き、負荷を確認します。Chromeは最小化しません。マイクはOBSで別に設定します。

6．終了・更新・設定の保存

接続画面の「中継を終了する」を押して、モデル画面も閉じます。次回は「起動.command」を開きます。モデル側の「停止」はモデルへの入力を止めるだけで、中継そのものの終了とは別です。

更新版を受け取ったら旧中継を終了し、新しいフォルダを解凍して起動します。IPはMacの ~/Library/Application Support/KamikanBridge/owl-prince/connection.json へ自動保存されるため、同じユーザーのMacなら更新後も残ります。このファイルを自分で編集する必要はありません。モデル画面の感度・較正は今回の版ではページを開き直すと初期状態に戻ります。

7．困ったとき

症状対処
ポートが使用中／EADDRINUSE以前の中継や別の同時起動を終了します。旧版は元のターミナルでControl＋C。別の作業中のプロセスを勝手に終了する必要はありません。
設定画面は開くが受信0同じWi-Fiか、iPhoneの現在のIPか、VTube Studioの送信設定がONか、21412番かを確認。ゲストWi-Fiでは端末間通信が遮断される場合があります。
受信しているがFaceFound=falseiPhoneのカメラに顔全体を明るく映します。VTube Studioを前面にし、顔追跡を開始します。
接続画面で顔検出中だがモデルが動かないセット内のモデルを「モデル画面を開く」から開いてください。古いowl_prince.htmlはWebカメラ方式です。モデル画面の入力がiPhoneか確認し、停止していれば開始します。
設定を保存できない表示されたエラー文を配布者へ伝えます。ZIP内を編集したり、IPをターミナルへ入力する必要はありません。
重いモデル画面を複数開かず、まずOBSなしで確認。Chromeの表示を小さくする、不要な物理等をOFFにする方法で比較します。本セットは新しい描画軽量化版ではありません。

この配布物はMac向けです。クラウドでは模擬iPhoneのUDP→WebSocket→Chromiumで検証しますが、実Macのダブルクリック許可・実iPhone・OBSの最終確認は利用するPCで行ってください。
