# MOTION-4：横向き・かしげへの上下混入と、上向きの視線

利用者から「左を向くと上を向く、右かしげで少し下、左かしげで上」「上を向いたときは目を細めず視線を上へ」という依頼を受けた。実機の生データを取得して原因を特定したとは説明しない。v3は分離した回転ベクトルに残る上下成分をそのままモデルへ渡していたため、今回は横向き/かしげを優先する明示的な混入抑制を追加する。

## 上下混入の抑制

`viewer/iphone-motion-v4.js` の `isolatePitch` は、上限で切る前の左右/かしげ量の大きい方と上下量を比較する。上下がその75%以下なら上下を0にする。75〜100%の間は滑らかに上下の強さを戻し、上下が主な動きなら従来どおり上下へ反映する。左右と首かしげの値自体は変更しない。反転設定・感度・モデルの上限より前に行うので、左右やかしげが最大値へ達しても小さい上下成分だけが強く残ることを防ぐ。

これは横向き/かしげが主な斜め動作に含まれる、意図した小さい上下動も抑える仕様。すべての複合動作をそのまま再現する変更ではない。`pitchLeakRatio` は初期.75、0で抑制無効。正面の真の上下動はこの比率で弱めない。

## 上向きの目

`viewer/tracking-input-v4.js` で、抑制後のAngleYが上向きのときだけ、部分的なEyeBlinkスコアに対して目を閉じにくくする。上向き.5度以上でスコア.65までは開いたまま、.9以上の完全な瞬きでは閉じる。上向きの入りは連続的に補間する。通常時/下向きのまばたきの式と、左右独立の完全な瞬きは維持する。笑顔・驚きの表情制御も変更しない。

新しいexportだけで4つの黒目パーツ（通常左右・驚き左右）のAngleY視線移動を変更する。上+5度で上へ3px（旧1px）。下向きと正面の移動量は従来どおり。画像、メッシュ、マスク、白目、まつげの定義は変更しない。上向きの顔位置でも、白目/まつげ/マスクの変形後の頂点は旧版と一致し、黒目だけが追加で約2px上へ移動することを確認する。

## 配布・保存・戻し方

`dist/lunaris_iphone_motion_v4_mac.zip`。現在のセットを複製して保管し、html・bridgeの2フォルダを置き換える。許可済み起動.commandは従来のものを残す。古いモデルのタブを閉じ、起動.commandを開き直し、MOTION-4の画面からモデルを開いて正面でC。旧MOTION-3の有効な3方向設定は引き継ぎ、再記録は必須にしない。未設定なら初回4姿勢を記録する。

原本は `viewer/iphone-motion-v4.html` / `viewer/tracking-input-v4.js` / `viewer/iphone-motion-v4.js` と `kamikan-bridge/portable-motion-v4/`。再生成は `python tools/export_iphone_motion_v4.py` → `python tools/package_iphone_motion_v4_mac.py`。MOTION-3と以前の全HTML・ZIP・素材・共通runtimeは保持し、バックアップのセットで戻せる。版の取り違えとモデルSHAの検証は前版の仕組みを維持。

## 確認範囲

Node5件、旧MOTION-3から実パッケージで切り替える起動1件、ブラウザ6件が成功。左右/左右かしげに小さい上下成分を混ぜた検証用入力でAngleY=0、実際の上下が主な入力では上下回転を確認。軽いEyeBlinkの上向きで目が開いたまま、完全な瞬きでは閉じることを確認する。旧設定の引継ぎと再読み込み/C、表情切り替えも確認。

正面・下向き・横向き・笑顔・驚きの5姿勢は完成版と描画ハッシュが一致。上向きは黒目以外の目の頂点が旧版と一致し、黒目の上移動を検査。画像は `/workspace/iphone-v4-check/` で上向き・目を細めない上向き・左かしげを目視確認した。数値ログは `iphone-pitch-gaze-v4-trace.json`。

実iPhoneの身体の動きはこの環境から操作・観測していない。以上は混入を加えた検証入力、実中継、ブラウザ、描画画像での確認であり、実機の問題が解消したという確認ではない。
