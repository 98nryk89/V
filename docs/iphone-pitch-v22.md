# iPhone上下回転修正版 v2.2

利用者の実機ではv2/v2.1で「右や横を向くとうつむき、下を向いてもうつむかない」と報告された。旧検証は公式サンプルから仮定した軸のJSONを送っていたため、数学的な対応は検証できても、利用者の物理的な下向きとの対応を証明できなかった。公式Unity表示例をすべての受信環境で正しい軸対応と断定した旧記述は、この実機結果を優先して扱う。

## 修正

- 新版の初期対応はRotation.xの増加を下向き、Rotation.yを左右、Rotation.zを首のかしげとする。前版の上下・左右を交換し、上下の符号を修正。
- 上下・左右・かしげ・位置移動は独立。横移動の最大値や横回転の飽和を条件に上下へ切り替える処理はない。デッドゾーンを超えた軽い下向きから応答する。
- 範囲は上5度・下10度・左右/かしげ5度のまま。滑らかさ・位置移動・顔未検出の復帰・表情の仕様は保持。
- 受信軸を推測し続けないため、画面に「下向きが合わない場合」を追加。正面をCで記録し、実際に下を向いた姿勢を明示して上下軸と符号を検出する。残るx/yの片方だけを左右に用い、zはかしげのまま。
- 下向きの記録は約0.3秒の安定窓の中央値で行う。正面から3度未満、上下左右/かしげの混合、顔未検出・古い受信は受け付けず旧設定を維持。通常の横移動から自動学習しない。
- 向きの設定だけをlocalStorageへ保存。Cは正面を更新し、向きは保持する。保存不可なら当該ページでは動作し、再設定が必要と明示する。

## 配布と復元

`dist/lunaris_iphone_pitch_v22_update.zip` 内の `owl_prince_iphone_test.html` と `owl_prince_tracking_config_v22.json` を、バックアップした既存Macセットのhtmlフォルダへ入れる。フォルダ全体や起動ファイルは取り替えない。`http://localhost:8765/` の接続画面から開き直し、v2.2表示を確認してC。合わない場合だけ画面内の下向き調整を使う。

ソースは `viewer/iphone-v22.html` / `viewer/tracking-input-v22.js`。再生成は `python tools/export_iphone_pitch_v22.py` → `python tools/package_iphone_pitch_v22_update.py`。既存v2/v2.1・Webカメラ版・中継・素材・ランタイムは無変更。旧フォルダで起動すれば戻せる。

## 検証と限界

Node62件（新規7件）、ブラウザ4件成功。既存Mac配布ZIPへの2ファイル適用→模擬UDP→実中継→WebSocket→HTMLで、軽い下向き、左右回転、かしげ、最大位置移動を確認。反対軸/反対符号のデータを下向き記録で合わせ、再読み込みとCの後にも維持することを確認した。表情・瞬き・正面復帰も確認。

5姿勢で完成版とキャラ描画のハッシュ一致。下向き・横向き・正面の画像を `/workspace/iphone-pitch-v22-check/` で目視。画像/メッシュは変更していない。実iPhoneをこちらから操作できないため、利用者の身体の動きとの一致は実機で次に確認する。合成入力のみで実機まで直ったとは断定しない。
